# 项目结构

工程只有一个 `app` 模块，使用 Kotlin、View/XML、AIDL 和 OpenGL。

## 连接怎么走

蓝牙 iAP2 交换热点和端点信息，手机加入车机网络，再通过 mDNS 发现 AirPlay 服务。配对完成后，视频走 H.264，音频走 RTP；车机触摸按 CarLife 触摸协议回传手机（不再依赖内置 shell 或虚拟屏）。

## 代码放在哪

| 目录或类 | 负责什么 |
| --- | --- |
| MainActivity、phone、ui | 手机首页、设置、授权和页面状态 |
| session | 连接状态、取消、重连和资源释放 |
| bt、iap2、net、airplay | 蓝牙、网络发现、配对和协议通信 |
| launcher | 车机桌面、应用启动、地图分屏和官方组件 |
| render | 把虚拟屏合成为编码器画面 |
| input | 触摸坐标换算和派发 |
| video、audio | 编码、推流和音频反馈 |
| service | 连接前台服务与会话生命周期（原 `shizuku` 内置无线 ADB 与 shell 服务已移除） |
| media | 媒体状态、歌词和天气 |

`SessionController` 管理整个连接，手机界面读取 `SessionSnapshot` 展示状态。取消或断开时先更新状态，再在后台释放资源；旧连接的回调不能改动新连接。

## 显示与线程

车机画面由 Dock、应用、超采样应用和地图虚拟屏合成，竖屏布局不使用超采样屏。触摸按最近一次成功提交的画面换算；Android 坐标从顶部算，GL 坐标从底部算。

短任务使用 `Bg`，推流、收包和 GL 循环使用独立线程。shell 调用、图片解码和文件读写放在后台。官方音乐组件使用标准 RemoteViews，隐藏后停止订阅。

包名、AIDL 接口、偏好键和配对身份参与安装或协议兼容，调整它们前要检查调用方和已有数据。
